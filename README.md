# يوميات — Yawmiyat

تطبيق ويب عربي (RTL) لإدارة الشركات والموظفين والمهام والجداول والمرفقات، مبني باستخدام Python وFlask.

> **الحالة:** هيكل أولي قابل للتشغيل والتطوير. تسجيل الدخول والتسجيل المحليان موجودان، ومخطط البيانات موجود. إدارة الشركات/الموظفين/المهام والجداول والمرفقات عبر واجهات CRUD، وتكامل Google والدفع الإلكتروني، لم تُنفّذ بعد. لا يوجد ربط بقاعدة بيانات Netrun.

## المتطلبات
- Python 3.10 أو أحدث
- pip
- بيئة افتراضية موصى بها

## التشغيل المحلي (Windows PowerShell)
```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
$env:AUTO_CREATE_DB = "1"
python app.py
```
افتح `http://127.0.0.1:5000`. عند أول تشغيل، ينشئ `AUTO_CREATE_DB=1` جداول SQLite داخل مجلد `instance/`. لا تُفعّل هذا الخيار في بيئة إنتاج دون خطة ترحيلات ونسخ احتياطي.

## التشغيل على Linux/macOS
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export AUTO_CREATE_DB=1
python app.py
```

## تشغيل الاختبارات
```bash
python -m pytest -q
```

## النشر على استضافة تدعم Flask / Netrun
1. أنشئ خدمة Python/Flask في Netrun واختر مستودع GitHub والفرع بعد مراجعته ودمجه يدويًا.
2. استخدم إصدار Python الذي تدعمه المنصة (3.10+).
3. أمر تثبيت التبعيات: `pip install -r requirements.txt`
4. أمر التشغيل المقترح: `gunicorn --bind 0.0.0.0:$PORT app:app` (عدّل الصيغة وفق تعليمات المنصة).
5. أضف `SECRET_KEY` كمتغير بيئة عشوائي قوي، وليس داخل Git. فعّل `COOKIE_SECURE=1` عند استخدام HTTPS.
6. عيّن `DATABASE_URL` إلى قاعدة بيانات مستقلة مخصصة لهذا التطبيق فقط. **لا تستخدم عنوان قاعدة بيانات Netrun الحالية ولا تغيّرها.** لا يتم الاتصال بأي قاعدة بيانات خارجية افتراضيًا.
7. جهّز تخزين ملفات خاصًا وآمنًا للمرفقات قبل تفعيل الرفع؛ لا تحفظ الملفات الحساسة في مجلد عام.
8. اختبر الصحة عبر `/health`، ثم اختبر التسجيل وتسجيل الدخول والصلاحيات على نسخة staging.
9. لا توجّه نطاق الإنتاج ولا تدمج التغييرات تلقائيًا. نفّذ مراجعة بشرية واختبار قبول قبل النشر.

## الأمان والحدود الحالية
- تُخزّن كلمات المرور باستخدام `Werkzeug` password hashing وليس كنص عادي.
- لا توجد مفاتيح OAuth أو بيانات دفع أو كلمات مرور في المستودع.
- حماية الجلسة وخصائص بعض ترويسات الأمان مفعلة. يلزم إضافة CSRF protection، تحديد معدل محاولات الدخول، استعادة كلمة المرور والتحقق من البريد قبل الاستخدام العام.
- التسجيل العام يمنح الدور `employee` افتراضيًا؛ لا توجد حاليًا واجهة آمنة لإنشاء المديرين أو إدارة الأدوار، ويجب إضافة صلاحيات إدارية محكومة قبل الاستخدام المؤسسي.
- نماذج البيانات للشركات والمهام والجداول والمرفقات هي أساس بنيوي فقط؛ الواجهات وإجراءات الإدارة لم تكتمل.
- لم يتم إعداد تسجيل Google أو الدفع الإلكتروني، ولا ندّعي أنهما يعملان.
- لم يُختبر النشر على Netrun؛ الخطوات أعلاه قالب عام ويجب مطابقتها مع واجهة المنصة الحالية.
